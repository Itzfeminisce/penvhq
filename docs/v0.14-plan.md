# v0.14 plan — the config speaks each provider's language

> **Status: active.** Decided 2026-09-01, in deliberation over a real wound:
> penv-cloud — penv's own hosted product — declares its production provider as
> `{ type: "@penvhq/provider-vercel", location: "penv-cloud", targets: { production: "production" } }`
> plus a separate `keys: { production: { source: "env", id: "production" } }` block.
> Every field name there is penv's vocabulary, not the provider's: `location` for
> what Vercel calls a project, `targets: { production: "production" }` restating
> one fact twice, `type` for what is a provider package, and the key declaration a
> screen away from the environment it belongs to. Three parallel top-level
> structures (`environments` the list, `providers` the record, `keys` the record)
> describe one thing: what each environment *is*. This milestone merges them and
> deletes the generic vocabulary. The [RFC](./RFC.md) gains the dated decision
> paragraph (the `location` rationale at its §"one generic address field" is
> overturned by this plan); this file owns *how*, and in what order.

**One framing to carry through.** An environment entry is the complete
declaration of that environment: which provider holds it, addressed in that
provider's own words, and which key seals it. Nothing about an environment lives
anywhere else in the config, and no field name asks the developer to translate.

---

## The settled surface

```ts
export default defineConfig({
  environments: {
    development: "@penvhq/provider-filesystem",
    test: "@penvhq/provider-filesystem",
    production: {
      provider: "@penvhq/provider-vercel",
      project: "penv-cloud",
      keySource: "env",
      // target: "preview",   // defaults to this environment's name
      // teamId: "team_…",
    },
  },
  defaultEnvironment: "development",
  publicPrefixes: ["NEXT_PUBLIC_"],
  override: { "workos/redirect-uri": "NEXT_PUBLIC_WORKOS_REDIRECT_URI" },
});
```

Everything outside `environments` — `defaultEnvironment`, `publicPrefixes`,
`override`, `schemaFile` — is untouched by this plan.

## Settled decisions (do not relitigate)

1. **One `environments` record replaces three structures.** The old
   `environments: string[]` list, `providers` record, and `keys` record merge
   into a single `environments: Record<string, PackageString | EnvironmentEntry>`.
   The record's keys *are* the whitelist — invariant 10 stands exactly as
   written, because a record key is a declaration, not an inference. Everything
   that consumed the old list (`assertEnvironment`, `reservedTokensFor`,
   `UnknownEnvironmentError` callers) reads `Object.keys(config.environments)`.

2. **String shorthand, only for config-free providers.** An entry may be the
   bare package specifier string when the provider's declared shape has no
   required fields beyond the discriminant — filesystem and mock today. At the
   type level: the shorthand arm is legal iff `{} extends` the declared shape
   minus core's reserved fields. At runtime: a string entry naming a provider
   whose declared shape has required fields is a config error naming those
   fields. An entry that needs any field is the object form.

3. **`type` becomes `provider`, and it is always a plain package-specifier
   string.** Never a factory import: provider packages are integrity-pinned CLI
   extensions recorded in `.penv/state/manifest.json`, not necessarily installed
   dependencies, so `penv.config.ts` must stay data-only and importable in a
   repo where no adapter code exists. Typing continues to come from the
   committed declarations under `.penv/state/extensions/`.

4. **Core's generic `location` is deleted.** Each provider declares its own
   named fields via the existing `ProviderConfigMap` augmentation, flat at the
   environment-entry level. The settled names, taken from each provider's own
   vocabulary (the factories already translate to exactly these concepts):

   | Provider | Old | New |
   |---|---|---|
   | vercel | `location` | `project: string` (required — id `prj_…` or name) |
   | vercel | `targets: Record<env, target>` | `target?: "production" \| "preview" \| "development"` |
   | vercel | `teamId?` | `teamId?` (unchanged) |
   | github | `location` (`owner/repo`) | `repository?: string` (optional; the ask-`gh`-once fallback keeps its exact semantics, renamed only) |
   | ssm | `location` (default `penv`) | `path?: string` (default `"penv"`) |
   | vault | `location` (default `penv`) | `path?: string` (default `"penv"`) |
   | kubernetes | `location` (`namespace/secretName` packed) | `secret?: string` (default `"penv"`) and `namespace?: string` (default: the kube context's) — the packed string dies; two facts get two fields |
   | filesystem, mock | — (config-free) | string shorthand |
   | penv-cloud | already its own fields (`url`, `tokenEnv`, `awsAuth`, `keypairAuth`) | unchanged, discriminant only: `type` → `provider` |

5. **`targets` becomes singular `target`, defaulting to the environment's own
   name.** A per-environment entry only ever mapped one environment, so the
   record shape restated its own key. `target` omitted means the target named
   like the environment; an environment name that is not a valid Vercel target
   and declares no explicit `target` is a loud refusal at provider construction
   naming both remedies — never a guess at a mapping (invariant 21's spirit at
   the provider level). `checkTargetEnvironments` and `resolveTarget`'s
   record-walking die with the record.

6. **`keys` becomes per-environment `keySource`.**
   `keySource?: "env" | "keychain" | { source: "env" | "keychain"; id: string }`.
   The string shorthand means the key id defaults to the environment's name;
   rotation to a differently-named key declares the object form. Omitted
   `keySource` means no sealing key for that environment (today's
   missing-`keys`-entry behavior; the null-source message updates to name
   `keySource`). **The artifact identifier format is preserved byte-for-byte:**
   `keySourceIdentifier` stays `${source}:${id}`, and because the defaulted id
   *is* the environment name, a config migrated 1:1 produces identical
   artifact bytes (`env:production` before and after). Invariant 15 (no key
   source ever falls back) and the tri-state `found`/`absent`/`unavailable`
   are untouched. `PENV_KEY_<ID>` naming via `envVarFor` is untouched.

7. **Core reserves four field names in every provider's declared shape:**
   `provider`, `keySource`, `key`, `keyId`. Enforced where the shape enters the
   system — `penv add`'s declaration generation refuses a `penv.types` file
   declaring any of them — so a collision is impossible by construction rather
   than checked on every load.

8. **One migration error, no compat shim.** A config where `environments` is an
   array, or where a top-level `providers` or `keys` key exists, fails at load
   with `CONFIG_ENVIRONMENTS_MERGED` (precedent: `CONFIG_NAMES_RENAMED`),
   whose message names the exact moves: the three structures into one
   `environments` record, `type` → `provider`, `location` → the provider's own
   field (naming vercel's `project` as the example), `targets` → `target`,
   `keys.<env>` → `keySource`. Error-message voice per AGENTS.md: name what is
   wrong, say the fix. The old shape has no other landing — every remedy string
   in the codebase that teaches `type:`/`location:`/`targets:`/`keys:` is
   updated to the new shape (~20 sites; the sweep list below).

9. **Ad-hoc push destination dies.** `penv push --destination <pkg> --location
   <place>` let a push go somewhere the config never declared — a hidden seam,
   and with provider-specific field names there is no generic slot to hang
   `--location` on. Both flags are deleted; push always uses the environment's
   declared entry, and `NO_DESTINATION`'s remedy teaches the config edit only.
   Seeding a new provider before cutover is done by declaring it first, which
   ongoing use requires anyway.

10. **Typing machinery.** `ValidatedProviders`/`ValidatedProviderEntry` become
    `ValidatedEnvironments`/`ValidatedEnvironmentEntry` over the new record:
    the object arm discriminates on `provider`, unknown declared-provider
    fields keep the readable sentinel (`"${K} is not a field ${P} declares"`),
    an unknown package keeps the open shape (typing is a reward for the
    committed declaration, never a requirement), and the string arm is
    constrained per decision 2. `UnknownProviderFields`' literal `"type"`
    exclusion becomes the reserved-field set. Compile-time requiredness of
    `target` conditioned on the environment key is deliberately skipped — the
    runtime default plus loud refusal is the whole contract.

## The silent-break sweep — every site the compiler will not catch

The verify stage hunts these specifically; the implementing slices own them:

- `packages/launcher/src/config-edit.ts` — the `providers\s*:\s*\{` scan regex
  and the `key.key === "type"` literal; the scanner must handle the string-
  shorthand arm (a non-`{` entry value is now legal, not a bail).
- `packages/runtime/src/child-env.ts` `strippedVariables` — iterates
  `Object.values(config.providers)`; a missed rename here leaks provider
  credentials into `penv run` children. Highest consequence in the repo.
- `packages/runtime/src/resolve.ts` `hasRemoteSource` — `own(config.providers, env)`
  and `.type !==`.
- vercel `factory.ts` bracket literals `?.["targets"]`, `?.["teamId"]` —
  invisible to a rename.
- Every raw `config.providers[environment]` index (cli `project.ts`,
  `doctor.ts`, `push.ts`) — after the reshape an untouched site reads
  `undefined` and silently treats a remote environment as the local tree.
- Every `own(config.keys, env)` (core `keys.ts`, `validateKeys`) — an untouched
  site resolves the null source and encryption silently degrades, with
  artifacts stamped `none`.
- The `Array.isArray(config.environments)` guards — their polarity inverts.
- `packages/core/src/types.ts` `UnknownProviderFields`' literal `"type"`.
- ~20 remedy strings teaching the old shape (grep `type: "@penvhq/` and
  `location:` across `src/`).
- Literal-word test assertions (`/location/`, `/targets/`) in vercel, github,
  and cli tests.
- cli `env-flags.ts`'s `"location"` flag and `push.ts`'s `--destination`.
- The smoke suites (`pnpm test:artifact`) are not in `pnpm test` — the gate
  runs them explicitly; they are the only tests proving committed declarations
  bind `defineConfig`.

## Build order

Integration branch `feat/config-redesign`; slices in worktrees, code-only
(fresh worktrees carry no `node_modules`; the gate runs once, post-merge, in
the main tree):

1. **core** (first, in the main tree — everything downstream needs its types):
   `types.ts`, `config.ts`, `keys.ts`, `grammar.ts`, `errors.ts`, `index.ts`,
   their tests and `config.test-d.ts` rewritten wholesale.
2. `slice/providers-a` — vercel + github.
3. `slice/providers-b` — vault + ssm + kubernetes + filesystem + mock. The
   contract suite (`providers/contract`) gets **zero edits** — it never touches
   config, and an edit there is a leaked abstraction to surface, not push
   through.
4. `slice/launcher` — `config-edit.ts`, `add.ts`, `declaration.ts` (base shape
   emits `provider`, reserved-field refusal) + tests
   (`declaration.test-d.ts`'s core-owns-`location` assertion dies).
5. `slice/cli-runtime` — `init.ts` scaffold, `doctor.ts`, `push.ts`,
   `project.ts`, `registry.ts`, `commands/key.ts`, `commands/run.ts`,
   `env-flags.ts`; runtime `resolve.ts`, `child-env.ts` + tests.
6. `slice/docs` — Documentation.md (canonical example, keys table, Providers
   section, GitHub and Vercel blocks, encryption example), RFC dated decision
   paragraph, Roadmap, provider-contract.md if it renders config; the
   changeset (hand-named kebab file, whole `@penvhq/*` fixed group, minor,
   bold-lead prose).
7. **provider-penv-cloud** (penv-cloud repo, own worktree) — discriminant and
   base-shape migration, remedy strings, its `penv.types` declaration.

**Gate.** After merge: `pnpm typecheck && pnpm test && pnpm lint` plus
`pnpm test:artifact`, once, in the main tree; the provider contract suite
passes unchanged for every provider. Then the adversarial verify pass walks
the silent-break sweep against the merged diff before anything is trusted.

## What this plan deliberately does not do

- **It does not touch the provider contract.** Field names are config surface;
  `capabilities`, `holds`, `readsValues`, and the 34 shared contract tests are
  out of scope, and a slice that thinks it needs a contract edit has found a
  design question to surface.
- **It does not add compile-time `target` requiredness keyed by environment
  name.** Decided against: the machinery cost is real and the runtime refusal
  is already loud, immediate, and names the fix.
- **It does not keep a compat shim.** One release, one migration error that
  teaches the whole move — the `names` → `override` precedent, applied to the
  config's spine.
